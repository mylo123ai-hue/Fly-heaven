# FLY-001 — One-fly simulator foundation and benchmark

## GOAL
Establish a reproducible **single-fly** local simulation foundation for Fly Heaven by adapting an existing open-source, connectome-derived fly simulator, then provide a truthful, repeatable benchmark procedure for the owner's **NVIDIA RTX 3070 8 GB**. This is **Phase 1 only**; do not build the paradise, full neural viewer, video workflow, or an unrelated new neural/physics engine.

Repository: `mylo123ai-hue/Fly-heaven`. Target environment for eventual owner-run validation: Windows + WSL2 Linux, NVIDIA RTX 3070 8 GB, 16 GB RAM. Codex Cloud is not the owner's PC and has no authority to access it.

## SCOPE
- Inspect current upstream scientific simulator(s) and dependencies, using **Fly.exe** as the initial candidate and FlyGym/NeuroMechFly and MaleCNS as relevant upstream references. Verify actual APIs, data sources, licences, revision compatibility and upstream assumptions before integration. Reuse existing software; choose the simplest supportable pinned setup. If Fly.exe is blocked, document the issue and propose an in-scope recovery using an existing scientific implementation, never fabricate a successful simulation.
- Create a minimal reproducible project foundation on a Codex **task branch**, with documented dependency versions, install/setup instructions, and a runnable single-fly smoke/benchmark entry point or wrapper. Do not vendor large upstream datasets, weights or third-party repos into Git history. Respect upstream licences, data attribution and download terms.
- Enforce **exactly one simulated fly** in examples and execution. Produce bounded run parameters and a method to capture elapsed wall time, simulated biological time, real-time factor, peak GPU VRAM (where CUDA is available), system memory where practical, model/config revisions, and success/failure status.
- Provide safe, copyable local WSL2/RTX 3070 benchmarking instructions for the owner to execute later manually. Clearly mark all owner-hardware measurements as **NOT RUN** unless genuinely performed on that hardware. Never claim cloud GPU metrics are RTX 3070 evidence.
- Include tests and a modest smoke check appropriate to the actual execution environment. Distinguish verified run/test results from static inspection, simulated fixtures and unavailable CUDA/datasets. Document provenance, model simplifications (e.g. engineered gait, object-vector perception) and scientific limitations; never describe this as a faithful conscious fly.
- Keep work narrowly focused on the Phase 1 integration, benchmark reproducibility and documentation. Codex chooses implementation details and can repair routine in-scope failures.
