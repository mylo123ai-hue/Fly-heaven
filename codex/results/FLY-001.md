# FLY-001 results

**Status: PARTIAL**

## Summary

Added a pinned, license-aware wrapper and reproducible procedure for running exactly one simulated fly through the existing Fly.exe / MaleCNS Virtual Fly project. The wrapper checks the selected upstream revision and one-fly interface, bounds the run to at most 1.005 simulated seconds, validates the upstream run summary, and records timing, configuration and available hardware telemetry.

The actual connectome run and RTX 3070 benchmark are **NOT RUN**. The authorized handoff prohibits accessing the owner's PC. No owner hardware was accessed and no GPU measurements are claimed. The wrapper's empty-data preflight was tested separately and correctly returned `not_run` without sampling GPU telemetry.

## Owner-only RTX 3070 command

After following setup and data/calibration steps in `docs/PHASE-1.md` on the owner's WSL2 machine, run:

```bash
"$FLYSIM_DATA_ROOT/envs/production/bin/python" \
  "$FLYHEAVEN_DIR/tools/benchmark_one_fly.py" run \
  --upstream-repo "$FLYEXE_DIR" --data-root "$FLYSIM_DATA_ROOT" \
  --duration-s 1.005 --seed 1 \
  --output "$FLYSIM_DATA_ROOT/runs/FLY-001/rtx3070-1.json"
```

Use fresh output paths for the smoke command and the two additional repetitions. The required calibration artifact is produced by the pinned upstream search, whose contract covers 108 candidates at 5.25 biological seconds per candidate. If it selects no operating point, or the GeNN build fails, retain the error and do not substitute hand-picked parameters.

## Known issues, risks, and rollback

- The pinned upstream project describes itself as pre-alpha. The selected route uses an engineered walking gait and object-vector visual encoding; it is not a conscious fly, a validated whole-animal model, or biological evidence.
- The MaleCNS starter raw inputs total about 1.9 GB, with further space needed for the environment, derived graph, compiled code and run outputs. Check free space first.
- CUDA Toolkit version is not pinned by Fly.exe. The wrapper records `nvcc --version` when available, along with the PyGeNN version and driver. Compatibility of GeNN 5.4.0 with the owner's exact RTX 3070 / WSL2 setup remains unknown until that machine runs it.
- GPU and system-memory peaks are sampled globally and may include unrelated activity; polling can miss brief peaks. These are run diagnostics, not isolated per-process VRAM attribution.
- If the selected upstream API or pinned dependencies fail, stop and record the blocker. Changing simulator or source revision requires a new authorized handoff.
- Rollback: close the unmerged PR or revert the task branch. Downloaded data, compiled artifacts and benchmark outputs are outside Git and remain under the owner's chosen data directory.
